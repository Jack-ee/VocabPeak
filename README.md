# VocabPeak · 高考英语词汇

给中国高中生用的英语单词学习 PWA。围绕真实的记忆规律构建：内置高中词库开箱即用、间隔重复（SRS）安排复习、选择题测验自动标记薄弱词、AI 批量补全音标释义搭配例句、巩固短文把本组的词放回语境里做选词填空。全程离线可用，家长可通过独立后台远程查看学习记录。

由 [EMPro](https://jack-ee.github.io/EMPro/)（面向科研人员的英语工作台）fork 而来，与 EMPro 部署在同一 GitHub Pages 源下。两者通过严格的命名前缀隔离，互不干扰（详见下文"与 EMPro 的同源隔离"）。

## 项目状态

活跃的个人项目。核心链路（单词页 → SRS 复习 → 测验 → 巩固短文 → 云同步 → 家长后台）已系统性排查并配有回归测试。"训练"和"阅读"页可用但打磨较少。Expressions、Writing Lab、口语教练等 EMPro 遗留模块已用 `display:none` 隐藏，代码保留但不参与本应用的功能面。

## 功能

### 单词（主页面）

- 三种视图：卡片、列表、测验（中文四选一）。中文释义默认隐藏，点"中文"按钮或按空格显示
- 分组学习：默认 50 词一组，组大小可在设置里调；进度按筛选分别记忆
- SRS 复习："复习"筛选列出到期词，四档评分（忘记 / 困难 / 良好 / 容易），间隔 1、3、7、14、30、60 天，容易翻倍
- 焦点标记：核心 / 发音 / 拼写手动标记；测验与课文填空答错自动标"薄弱"，连对 4 次且分布在 3 个不同学习日才摘除（真实掌握才毕业，不随时间消失）
- 自动播放：按 词 → 英文释义 → 中文释义 → 搭配 → 例句 顺序朗读整组，播放期间屏幕常亮，各环节可在设置里单独开关
- 打乱：仅视图层洗牌，不改存储顺序，种子固定保证翻页连贯

### 内置词库与导入

- 内置高中词库（核心 + 拓展），首次运行自动载入核心词。守卫条件：未载入过、生词本为空、本机未配置云同步，三者同时满足才载入，绝不覆盖已有数据
- 统一词库 lexicon-3500.js（v148）：《英语·单词本》3500 词（默写本的英文列是空的，英文词头按音标、中文与字母序逐条还原，并校正了源文件约 134 处音标错误）与内置高中词库合并，共 3876 个词头，分四级：H 高中核心、E 高中拓展、J 初中·值得学、B 非常简单。导入弹窗里的「载入 3500 新增词」只追加 E、J 两级里生词本还没有的词（带音标、释义、搭配），已有词条和学习记录不动，只给缺音标的已有词补音标；B 级不进生词本，但阅读时照样能点词查到
- 粘贴导入：支持一行一词、`词 | 释义 | 搭配`、逗号分隔等多种格式，命中离线词典的词自动带中文释义
- 批量 AI 补全：一键复制本组待补全词的提示词 → 到 Claude.ai 粘贴 → 把回复回填。回填按 INPUT 字段精确匹配原词行，词形变化（squeezed → squeeze）自动归并到词元，已有中文释义和 SRS 复习进度原样保留

### 巩固短文（选词填空）

针对当前分组生成 2-3 篇短文，目标词挖空为四选一。同样走"复制提示词 → AI → 回填"流程，解析对缺 TITLE、多余空行、格式异常的空等情况均有容错。短文按（筛选, 组号）存储并随云同步。

### AI 短文（v148）

课文页顶部「教材课文 | AI 短文」切换。AI 短文按默写本字母顺序推进，每篇 20 个以上目标词、250–420 词，十种体裁轮换（记叙、科普、新闻特写、访谈、书信、日记、议论、传记、游记、演讲），难度对准高一。v148 发布 107 篇，共 2306 个目标词，覆盖 3500 词表里全部非简单词。其中 S0106、S0107 是补充篇，按教材和学生英文报纸的写法，用平实中立的语境集中讲 prison、tobacco、communism、divorce 等 20 个题材敏感的考纲词（补充篇目标词下限放宽到 10）。每篇都经独立编辑核对事实、搭配、指代与场景，事实依据写在源稿开头的 `# 事实` 注释里。与教材课文分开存放和统计，但听读、点词、填空、短语四步完全共用，学习记录照常同步。

- 点任意词查词：「点词查词」模式下点文中任何词，按统一词库 → 本篇注释 → 离线词典逐级查释义，自动还原词形（accepted → accept、taught → teach），非基础词可一键入生词本（原型、音标、释义，本句作例句）。生词本里已有的词只补空字段，整理过的释义、搭配、例句不会被一句语境释义盖掉（教材课文的点词入本与答错强化同样如此）。教材课文默认仍是「点句听句」，两种模式随时切换，各自记住
- 朗读：每篇固定一个朗读者音色，句子用"自然叙述"的要求合成进发音包
- 发布：源稿在 tools/stories/src/，`python tools/stories/build_stories.py` 校验（目标词数、跨篇不重复、超纲率不超过 4%、每句有译文、超纲词必须有注释）后写入 stories/，提交即被应用增量拉取，同时触发发音包构建
- 存储：短文是发布物，存本机 IndexedDB hsv_stories，不进 Gist

### 训练与阅读

- 训练：同义词辨析、搭配选择的即时刷题（内置题库，无需 API），以及 AI 生成的进阶题
- 阅读：粘贴文章提取生词，按级别和类型筛选后一键存入生词本

### 家长后台（dashboard.html）

独立页面，用同一 GitHub 令牌只读拉取孩子的同步 Gist，不改动任何数据。展示连续学习天数、今日与近 7 天的新词/复习/测验量、词汇掌握分布、18 周学习热力图、课文学习时长、AI 短文进度（v148，单独成表）、逐日明细和薄弱词清单。家长浏览器只存自己的 `vpdash_` 前缀设置，不触碰应用数据。

## 数据与同步模型

所有学习数据存在浏览器 localStorage（键前缀 `hsv_kid_`），无后端、无遥测、无账号。

云同步为可选项，基于 GitHub Gist：

- 推送整份快照；拉取时按键合并而不是整份覆盖（v147）：生词本逐词合并（学习状态、焦点标记、内容字段各取较新的一侧，删词靠墓碑传播），课文记录字段级合并，统计取最近学习日晚的一侧，同日天记录取活动量大的一条，其余设置后写覆盖。加载、聚焦、可见性变化和每 30 秒轮询时拉取，数据变更后 3 秒防抖推送；推送失败会标记待上传并在联网后自动补推
- 同步文件名 `hsv-sync-kid.json`，档案 ID 在 config.js 写死为 `kid`，换设备、清缓存、重装都指向同一份数据
- 按天日志用独立键 `day_YYYY-MM-DD`，两设备在不同日期学习互不覆盖；拉取合并对 day 键"只增不删"，离线几天的记录不会被其它设备的快照抹掉，恢复联网后自动把并集补推上云。远端快照缺少某个设置键时同样保留本机值，不当成删除
- 纯本机键（单词页组内位置、打乱状态、测试设备开关、调试面板开关）不进推送快照、不被远端覆盖（v147 起真正生效；此前只是不触发推送，实际仍在同步）。测试设备开关开着时头部常驻「🧪 测试」标记
- 新设备首次配置令牌时先搜索已有 Gist 并拉取，找不到才新建，空设备不会覆盖云端数据

密钥策略：GitHub 令牌只需 `gist` 权限，仅存本机、永不入同步包。AI API key 默认不同步，需在设置里明确开启后才随 Gist 传播。OpenAI TTS key 无论如何都不进同步包。

## 离线与语音

安装为 PWA 后完全离线可用：Service Worker 预缓存全部本地资源（网络优先、离线回退），词典和词库随应用打包。Google 字体跨域不缓存，离线时回落系统字体。

发音走三级回退：

1. 离线发音包：预生成的单词与句子音频（GitHub Release 资产，经 Cloudflare Worker 中转下载），存在独立的 IndexedDB 库里永不淘汰，命中即播、零网络零密钥，单词每次随机换音色
2. 神经语音：OpenAI gpt-4o-mini-tts，经同一个 Cloudflare Worker 代理（浏览器无法直连 OpenAI），合成结果双层缓存（内存 + IndexedDB），每段文本每设备最多请求一次
3. 设备自带语音：最终兜底；中文文本始终走设备中文音色

发音包由 GitHub Actions 构建（`tools/generate_audio_pack.py` + `.github/workflows/build-audio-pack.yml`）：在设置里选音色、导出 wordlist.txt、替换 `tools/wordlist.txt` 并提交即触发增量构建；AI 短文不用导出，提交 stories/ 即触发。OpenAI 密钥只存在仓库的 Action Secret 里。

v148 起发音包分片发布：一个索引 `vocabpeak-audio-pack.index.json` 加约 44 个分片（单词表按词头首字母 w-a…w-z、课文语料按文本哈希 l-0…l-7、AI 短文每 10 篇 s-0001…）。分片文件名带内容哈希，新版本是新文件，工作流先传新分片、再传索引、最后删旧分片，任何一步失败旧索引都完整可用；索引丢了，下次构建从现存分片重建状态而不是从头重合成。一次构建要删掉 10% 以上已有片段时默认中止（通常是从没同步好的设备导出了单词表），确有需要在手动运行时勾选 allow_drop。应用只下载 sha256 变了的分片，逐片校验，全部对齐后再清掉旧音色和已删词的片段（已是分片包的设备一次最多清 20%，多了暂缓）；启动时每 12 小时看一次索引，25 MB 以内的更新自动补齐。生成器用 ffmpeg 把每个片段转成单声道 48 kbps、把词尾 1 秒多的静音截到 0.35 秒，同一遍检测出静音或截断的坏片段并重新合成（8 月的整包里有 233 个静音片段），并剪掉已下线音色。原有内容从约 1.6 GB 降到约 0.15 GB；加上 107 篇 AI 短文的朗读（约 4 小时音频）后全包约 0.26 GB。

## 快速开始

孩子的设备：

1. 打开 https://jack-ee.github.io/VocabPeak/ ，首次运行自动载入内置核心词，即可开始学习
2. 建议安装为 PWA（Chrome 菜单 → 安装应用），获得离线能力和独立图标
3. 云同步：在 https://github.com/settings/tokens 创建仅 `gist` 权限的令牌，粘贴到 设置 → Sync
4. 语音增强（可选）：部署 `vocabpeak-tts-proxy.js` 到 Cloudflare Worker，把 Worker 地址填入 设置 → Voice，即可使用神经语音和下载离线发音包

家长：

打开 dashboard.html，粘贴同一个 GitHub 令牌、档案 ID 填 `kid`，连接后即可查看。

网络提示：中国大陆访问 GitHub（同步、发音包）和 OpenAI（神经语音）需要科学上网；应用本体安装后离线可用，不受影响。

## 与 EMPro 的同源隔离

两个应用同源部署（jack-ee.github.io），localStorage、IndexedDB、Cache Storage 均按源共享、不按路径隔离，因此所有存储命名必须分家。本项目的约定：

| 存储 | EMPro | VocabPeak |
| --- | --- | --- |
| localStorage 前缀 | emp_ | hsv_ |
| 同步 Gist 文件名 | emp-sync-*.json | hsv-sync-kid.json |
| TTS 缓存库（IndexedDB） | emp-tts | hsv-tts |
| 发音包库（IndexedDB） | emp-tts-pack | hsv-tts-pack |
| SW 缓存名 | emp-vN | hsv-vN |
| 页面事件 | emp:datachanged | hsv:datachanged |

维护红线：任何代码不得读写无前缀裸键或 emp_ 键。回归测试对全部运行时文件做裸键扫描。

## 部署与缓存纪律

改动任何被缓存的运行时文件（index.html 引用的 JS/CSS）时，必须同时：

1. bump sw.js 的 `CACHE_NAME`（hsv-vN → hsv-vN+1）
2. 全文替换 index.html 里所有 `?v=N` 为 N+1

两者漏改任何一个都会造成"改了不生效 / 半新半旧"的诡异问题。README、dashboard.html、sync-test.html、tools/ 不在预缓存清单内，单独改动它们无需 bump。

## 测试

在仓库根目录运行 `npm test`（或 `node test/run-all.js`），无需安装任何依赖即可跑完全部测试；装了 playwright 时会额外跑一遍真浏览器冒烟测试。重点：

- test-load-v147.js：按 index.html 的顺序整文件加载全部脚本，按方法探测各模块。v142~v146 的 sync.js 加载即崩、同步停摆 7 周，当时的测试都是抽单个函数 eval，所以一直全绿
- test-sync-reconnect-v147.js：两台设备共用模拟 Gist，回放"断同步 7 周后重连"，要求平板复习进度一个不丢、两边最终一致且不互推
- test-release.js：发版纪律（?v= 与 CACHE_NAME 配对、预缓存清单齐全），每次发版前跑一次
- test-stories-v148.js：真浏览器整站加载，覆盖来源切换、短文增量下载与断网复用、点词查词与入生词本、点词模式本机记忆、「载入 3500 新增词」不动已有词条的 SRS/焦点/错题记录、家长后台短文统计
- test-quota-v148.js：localStorage 配额模拟，写学习记录撞配额时先让出拉取前快照
- test-sw-offline-v148.js：真 Service Worker 下断网检查短文，不得删掉本机篇目、不得把带 t= 的请求写进缓存
- test-pack-shards-v148.js 与 test_audio_pack.py：发音包分片端到端（生成器用假 TTS 现场造包）：旧整包迁移、剪掉旧音色与已删词、静音片段重合成、无变化时字节不变、只下载变了的分片、sha 不符时拒收且不剪枝、索引或分片丢失时从现存分片重建（只补缺的）、删减保护、并发同步、分片包设备不回退旧整包、剪枝保险。需要 ffmpeg，Python 测试由 run-all.js 一并运行
